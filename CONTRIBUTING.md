# Contributing

Run the build, strict TypeScript check, Node tests, Python/API/browser suite and build verification before proposing a change. Keep source and generated client catalog consistent. Browser integration fixtures must remain visibly marked as fixtures; do not replace actual observations with them in live mode.

Never put a provider key in browser code, add model-generated compatibility rules, reward speed or chemical experimentation, or equate visible improvement with hygiene. New catalog entries require source evidence, explicit scope/exclusions, review/expiry metadata and positive/negative parity tests. See docs/SAFETY.md.

Discuss changes to privacy, provider transport, scoring authority, persistence limits or public deployment separately. Do not upload real household photos containing people or private information in an issue or test fixture without appropriate consent.

Use clear commit messages and record the actual creation times. Publishing and the hackathon's code-window requirements are separate from passing tests.
