# Hackathon provenance and eligibility

This is a factual source-timing note, **not** an eligibility certification.

- **October 2, 2026:** The GrimeQuest concept and exploratory build work
  were discussed before Yard #4 officially opened. Some preparatory coding
  may have occurred before the contest window; the exact original-code
  boundary has not been independently reconstructed from full local records.
- **October 5, 2026, 18:00 UTC:** Yard #4 officially began.
- **October 6–9, 2026:** The project was published to a private GitHub
  repository, iterated and deployed to Railway, and later made public.
  GitHub subsequently identified the public canonical repository as
  **Smkzz/GrimeQuest**, replacing an earlier organization URL.
- **October 9:** The public player experience consists of a new,
  self-reported camera game with collectible fictional monsters. Historical
  practice/barcode/AI code remains in the repository but is not the visible
  current game. Runtime gameplay does not call a model or inspect cleaning
  quality.

Hackyard's [official rules](https://hackyard.tech/faq) explicitly allow
**planning and ideas before kickoff**, but say that code constituting a
builder's own project must be written during the build window. Starter
templates and third-party dependencies are permitted. The rules publish
GitHub repository timing and leave authenticity to voters, rather than
automatically disqualifying submissions.

**Owner action:** Before declaring full compliance with the coding window,
review any local pre-October-5 source/workspace copies and the actual
committed source history. Do not rewrite timestamps, backdate commits,
misrepresent older source as newly written, or claim independent proof not
present in the available evidence. If material project code was created
before kickoff, disclose it accurately and consider asking the organizer
how it should be treated.

GitHub and Railway builds verify software behavior, not authorship or
hackathon eligibility. The code's MIT license and third-party notices are
separate from the competition's source-timing requirement. A public repo,
a GitHub Release and a working hosted game are **not** an actual Hackyard
submission; the owner's final submission must be confirmed separately.
