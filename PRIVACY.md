# Prototype privacy boundaries

The source application contains no analytics, ads, tracking pixels or account SDKs. This describes the included code, not a complete legal policy for a future public service.

**On this browser:** inventory names/notes, up to 200 comparison records, mode-specific XP inputs and an interrupted-task warning are stored locally. Completion records may include signed result receipts and image digests, but never the photo bytes. The private application access code is in tab-session storage, separate from provider credentials. Exported journals do not contain access codes or photos. A shared or compromised device can expose local records. Private-browsing or storage restrictions may prevent persistence.

**In memory:** selected photos remain in the current page until the task is finished/abandoned, the selection is replaced, local data is deleted, or the page closes/reloads. Camera streams stop on navigation, visibility loss and page exit. Front/back product photos are cleared after saving/abandoning the product workflow. Closing a tab does not delete data already sent to a provider.

**At the server:** live images are bounded, decoded and re-encoded in memory, not written to the filesystem by application code. EXIF metadata is removed before provider submission. The application disables request access logs through `run.py`; it does not log image bodies, labels, keys or model text. Hosting infrastructure, proxies or a debugger could add logs; operators must verify their configuration. Temporary result caching contains bounded receipt metadata, not photos. Process restarts discard it.

**Worldwide community product identification (not OCR):** Barcode decoding from camera video or a still image happens **entirely within the browser** using a self-hosted JavaScript library. Neither images nor video frames are sent to GrimeQuest, Open Facts or Google. When a player scans a valid barcode or deliberately looks up entered digits, GrimeQuest automatically sends only the numeric EAN/UPC/GTIN to its backend and first to the worldwide Open Facts family of community APIs (Open Products Facts, Open Beauty Facts, Open Food Facts and Open Pet Food Facts). If there is no Open Facts match, it may also send those digits to UPCitemdb and EAN-Suche using their bounded, no-key product lookup APIs. A Google-backed Serper web query is attempted only as a last resort when the operator explicitly configures a server-side GQ_SERPER_API_KEY; no player-provided key, paid request, page scraping or web query occurs by default. If a player taps **Search products worldwide**, the typed product-name or brand query is sent to the GrimeQuest backend and to those same four community services. Queries are **not** transmitted on every keystroke. Open Facts, UPCitemdb, EAN-Suche and (when the operator enables it) Serper can process the numeric code and ordinary request metadata under their own terms. Only typed name searches go to Open Facts; no provider receives camera frames or barcode photos. GrimeQuest does not log queries or label images and stores only bounded ephemeral recent searches/results in server memory (up to 64 search terms cached for 1–3 minutes, 128 barcodes cached for up to one hour). Only a player-confirmed product name, optional barcode and notes are saved on the player's own device. No third-party descriptions, hazard text, product images or instructions are imported or persisted. No upstream chemical directions, warning text or permissions are imported. The user may skip all external lookups and enter a name offline. Optional **Search the wider web** links open Google Search in a separate browser tab **only on a user click**, passing the typed product name or GTIN to Google. No personal account, user photo or access token is appended by GrimeQuest, and the links use no-referrer. Google Search's independent privacy terms apply. Google Cloud Vision label OCR is absent from the product screen and remains operator-disabled.
**At the selected provider:** explicitly approved live requests send the normalized photo(s) via the operator's configured endpoint. Provider retention, use and regional-processing policies are external to this application. The UI shows the configured provider hostname. Read the actual provider terms before enabling live use. EXIF removal does not remove a face, address or private document visible in pixels. No automatic redaction is promised.

Guided Camera Quests are local: their before/after images are processed only on-device, and visible change is user-reported rather than inferred by a model. Neither guided camera quests nor practice illustrations need a provider call. The service worker caches only named public app-shell assets, not images supplied by a person, labels, API responses or secrets.

Deletion in Settings removes the app's local history, inventory and tab access code. It does not recall provider submissions, delete browser downloads or remove physical cleaner residues. A public service would need its own jurisdiction-appropriate policies, operator identity, retention controls and consent review; those are not supplied by this prototype.
